# WRF-Fire comparison for OpenBCEllipsoidBuffer

Same structure as `../../OpenBCRidgeCorner/wrf_comparison/`: the identical
physical setup (ellipsoid terrain, Open BCs on all four sides, 3 m/s @
34deg wind, top damping, horizontal advection order) run in WRF-Fire
instead of ERF, using WRF's file-based terrain input
(`fire_read_atm_ht`/`fire_read_fire_ht=.true.`, `input_ht`/`input_zsf`
generated by `gen_wrf_ellipsoid.py`, the same ellipsoid formula as ERF's
`../gen_ellipsoid_terrain.py`).

## Result

WRF stays stable (3 -> ~5.1 m/s peak, settling to 4.4 m/s by t=360s),
matching ERF's stability on the same terrain. See `../README.md` for the
full table and the conclusion this supports (terrain-boundary proximity,
not a general ERF Open-BC weakness, drove the ridge case's runaway).

## Build and run

Same WRF-Fire checkout as `../../OpenBCRidgeCorner/wrf_comparison/`
(`WRF4_fire/WRF`, v4.6.1, commit `d66e442f`).
```
mkdir case_ellipsoid_buffer_34deg && cd case_ellipsoid_buffer_34deg
# copy namelist.input, namelist.fire, input_sounding, input_ht, input_zsf
# from this directory, plus the standard WRF static data files (see
# ../../OpenBCRidgeCorner/wrf_comparison/README.md for which ones)
ln -s ../ideal.exe ../wrf.exe .
./ideal.exe
./wrf.exe
```
`namelist.input` here has `run_minutes = 6` (360s), shortened from the
ridge case's 45 min since this test only needed to match ERF's 300s
comparison window.
